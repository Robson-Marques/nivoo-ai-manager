# Execução enxuta — efeito no executor

Quando a Skill execucao-enxuta está ativa em uma etapa de software sem operação de mídia ou revisão de regras, o compositor de contexto limita o conteúdo histórico opcional a 6.000 caracteres de memória e 1.500 caracteres de lista de artefatos, dentro do orçamento global existente. A sessão recebe o último erro; as últimas cinco tentativas consultadas ficam disponíveis no arquivo de contexto. Regras, perfil, objetivo, critérios, etapa, referências e acervo integral permanecem disponíveis. Não se apagam artefatos, nem se afirma que uma cópia de arquivos por si só consome tokens. O modo de referência do benchmark mantém seu comportamento anterior. Os logs e contextStats registram o tamanho efetivo das parcelas limitadas.

O planejador deixa de exigir automaticamente a suíte global e o build em cada etapa de código, mantendo verificações proporcionais e validação integrada necessária. Nenhum comando já aprovado é silenciosamente substituído ou pulado. Scripts compostos ou hooks de projeto ainda podem repetir verificações; separá-los de forma válida exige conhecer seu contrato e dependências. Esta alteração reduz o contexto enviado, não prova economia de tokens do provedor. Use os registros NIVOO_TOKEN_BENCH e compare tarefas equivalentes com resultados funcionais equivalentes.
